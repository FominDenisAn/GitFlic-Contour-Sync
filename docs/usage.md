# Как пользоваться

## 1. Подключить контуры

В `Контур 1` и `Контур 2` указать URL GitFlic и API-токены, затем нажать `Войти`.

## 2. Указать runner

В поле `Тег раннера` указать tag runner, который имеет сетевой доступ к обоим контурам и настроенные Git credentials.

## 3. Выбрать проекты

Поиск выполняется независимо в каждом контуре. Слева выбрать проект, который является источником, справа - соответствующий проект назначения.

## 4. Выбрать ветки

После выбора проектов приложение загружает реальные ветки через GitFlic API. Выбираются конкретные ветки с обеих сторон, например `Pre-Prod` -> `Pre-Prod`.

Если проект создан, но в Git ещё ничего не запушено, приложение показывает, что ветки отсутствуют.

## 5. Сравнить изменения

Кнопка `Сравнить изменения` запускает read-only pipeline на выбранном runner. Runner:

- повторно проверяет SHA обеих веток;
- определяет направление Git-истории;
- строит точный diff между будущим и текущим состоянием Контура 2;
- считает добавленные/удалённые строки и изменённые файлы;
- выполняет `git push --dry-run`.

Если Контур 2 новее или истории разошлись, запись блокируется.

## 6. Просмотреть изменения

На вкладке `Изменения` отображаются файлы и построчный diff: что будет удалено из Контура 2 и что будет добавлено из Контура 1.

## 7. Обновить ветку

Кнопка `Обновить ветку` доступна только после успешной проверки.

Перед реальной записью runner заново получает обе ветки. Если source или target изменился после preview, push не выполняется. При неизменном состоянии runner обновляет только выбранную target-ветку и проверяет итоговый SHA.

## 8. Выполнение и история

Вкладка `Выполнение` показывает pipeline и jobs. Вкладка `История` хранит локальный журнал preview/push операций без токенов.
